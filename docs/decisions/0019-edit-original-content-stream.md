# 0019 对象编辑和涂黑写在原内容流上，PDFium 只读

2026-11-27 Claude 审核 v0.6.0 时定（站主交代「必要时直接优化代码结构」）。改了 `0010` 里「PDFium 负责移动删除和涂黑」的做法。

实测（38 份真实论文，检查程序在 `local/checks/edit-redact/`，原在 `local/v060/review/`）：PDFium 改完对象后整页重新生成内容流，会丢掉 `TJ` 的字距微调（整页字距都变）、偶尔丢掉整段内容（XGBoost 第 2 页右栏下半截消失），也会丢几个结构标记。涂黑原来只验框里，别处坏了照样交文件。

定的：

- **PDFium 只读**：列页面对象（`Document::objects`）、取字形框、解图片像素。
- **写由 lopdf 在原内容流上做**（`sys/content.rs`）：照 PDFium 列对象的规则数出每个对象由哪条指令画出，和 PDFium 的清单逐个对上（种类、图片落点）才动手，只改那几条指令，其余原样保留，标记内容和结构树不受影响。
  - 移动图片：前后包 `q cm … Q`。移动文字：用只挪位置的 `TJ` 和字高 `Ts` 包住那一段，行矩阵不动，同一行后面的字照旧。
  - 删除：去掉那条指令（路径改成 `n`）。同一行后面还接着画字时，按字宽表补回同样的前进量；字宽拿不准（标准 14 字体没有 `/Widths`、非 `Identity-H` 的 CID 字体、竖排）就拒绝。
  - 对不上清单、或页上有内联图片（lopdf 解析不全）时这一页不改：对象编辑报 `ObjectEditFailed`，涂黑改走整页位图。
- **交文件前核对**（`sys/check.rs`）：改动区以外，PDFKit 画出的像素（容许万分之一的亚像素差）和 PDFium 取出的字都要和原页一样。对象编辑过不了就报错，涂黑过不了就改走整页位图。
- **涂黑带结构树的页**（`sys/tags.rs`）：涂过的页上的结构元素连同上层去掉 `ActualText`、`Alt`、`E`；整页位图的页再去掉结构树里指向旧内容的引用和 `/StructParents`。只有 `/StructParents`、没有结构树的页（知网）照常涂。

没选的：PDFium 整页重写再加核对（多数论文会被拒或整页位图）；自己算每个字形的位置（要解析全部字体）。
