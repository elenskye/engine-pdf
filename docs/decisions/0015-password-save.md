# 0015 加密文件保存与权限位

2026-11-26。站主确认显式换密码或去密码，以及修改加密来源需要先用权限密码打开（ASK）。

- `Document::open_with_password` 及 `from_bytes_with_password` 使用 `Zeroizing<String>`。能打开仅设权限密码的文件时也验证输入是否获得所有者权限。`Save` 由 Rust 调用方提供，`remove_password` 与 `lock` 二选一。普通空改动返回原字节。
- 去密码时让 PDFKit 从已获所有者权限的文档导出，并核对页数、表单和逐页文字层。实测仅用 `lopdf` 0.42 读取旧安全处理器的所有者密码会生成错误的明文内容。
- 加密由 `lopdf` 写（128 位 RC4，R3，权限位照请求精确写），输出用 PDFKit 验证打开密码、权限密码和权限位（2026-11-26 v0.5.2 改）。不用 PDFKit 自己加密：它写出的加密表单在 Edge 里即使没有打开密码也不显示控件（`lopdf` 加密的同一文件正常），有的权限组合它还会多给批注权限。设了打开密码的表单，Edge 新版阅读器（Adobe 引擎）不管谁加密都不显示控件；Chrome、「预览」、PDF.js、PDFium 都正常，网上有同样的报告，站主定不处理（2026-11-26）。打开后用 `Info.permissions` 显示普通读者的实际权限位，所有者按当前权限显示。
