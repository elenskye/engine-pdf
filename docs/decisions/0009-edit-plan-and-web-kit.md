# 0009 编辑：一张改动单、引擎一处写文件、无样式的 PDF.js 套件

2026-11-25。套件的归属和验收方式由站主定（ASK），改动单和写入方式由 Claude 定。

- **改动单**（`edit::Plan`，可序列化）：页序（合并、插入、删除、旋转、重排、抽页）、加删标注、填表、目录、文件信息，都写成同一张单子。界面（`web/` 套件）、模型工具、App 自己的流程都产出它。
- **只有引擎写文件**：`edit::apply` 用 PDFKit 把改动单一次写成新文件的字节，交回 App，由 App 决定写回原处还是另存。不用 PDF.js 的 `saveDocument` 写文件，因为同一份标注有两种写法会画得不一样，模型工具、批处理这些没有界面的场景也只能走 Rust。PDFKit 是整份重写，不是增量追加，影响在 v0.5 Phase 1 实测；某类改动实测不行，再只给这一类改用 `saveDocument`，并改这份决定。
- **`web/` 套件**（站主定）：基于 PDF.js 6.5 的显示、切换工具、把编辑器内容换成改动单、页面整理、表单、目录编辑的逻辑，不带样式、不依赖界面框架。按钮和样子由各 App 用自己的设计系统画（Pith 的来自 Atelier 的 `pith` 方案）。这改了「界面归 App」的边界：**界面的样子归 App，PDF.js 上的编辑逻辑归引擎**。
- **验收**（站主定）：v0.5 用引擎自带的试用页（`examples/studio`，本机浏览器打开）。Pith 到 v0.8 接引擎时再接套件，写进原文件还是另存、和库里的标注怎么并存由 Pith 定。Pomelo、Peck 先用无界面的接口。

没选的：引擎只给 Rust 接口、界面各 App 写（编辑交互要写两三份）；引擎带完整的界面组件（要绕开各 App 的设计系统）。
