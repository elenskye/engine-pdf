# Pomelo 接 engine-pdf · 开发简报

> 2026-11-25 · 交给 Pomelo 的开发会话，据此制定详细开发计划。计划先给站主看过再开工。

## 目标

Pomelo 里处理 PDF 本身的代码（读字、画页图、拆合页面、照片打包、Mathpix 上传下载）全部改用共用引擎 engine-pdf，Pomelo 只留「拿 PDF 做什么」的业务。顺带拿到两项新能力：

1. **扫描件能进知识库**：本机 OCR 认出文字，能被搜索、带页码引用（现在扫描件只列文件名）。
2. **知识库里的 PDF 和扫描件保留页图**：模型看得到原页的样子（图表、公式、版式），看不看由模型决定。

## engine-pdf 现在能做什么

- 仓库：`~/Documents/GitHub/engine-pdf`（公开，GitHub `elenskye/engine-pdf`）。最新 tag `v0.3.0`；`v0.4.0` 正在接 Peck，Pith 排 `v0.5.0`，Pomelo 排 `v0.6.0`（要提前由站主定）。
- 能做：打开（坏文件、要密码、不是 PDF 分开报错）；逐页取文字，每页标明原文 / 本机识别 / 空白 / 没取到字 / 读失败；页码是原文件第几页，另给页面上印的页码；画页图（JPEG、PNG、灰度，范围和阅读器一样）；拆页；统计哪些页有图片；macOS Vision 本机 OCR（断网可用，简繁英，多栏按阅读顺序）；Mathpix（本地报价 → 确认后只传选中的页 → 结果映射回原页码 → 不管成败都删远端；分步接口可续跑；Word 也能传）。
- **逐页读取默认每页都附 1568px 页图**（空白页、读失败的页除外，`decisions/0007`）。只要文字、不给模型看的场景（建索引）要显式关掉。
- 引擎的代码当初就是照 Pomelo 的 `youzi/pdf.rs` 写的：同一个 macOS 组件、同样在 App 进程里调，速度一样。
- 必读：engine-pdf 的 `README.md`、`docs/design.md`（§1 接口、§3 Mathpix、§4.3 Pomelo 迁移）、`CHANGELOG.md`、`docs/decisions/`。

## 哪些进引擎，哪些留下

| Pomelo 里的东西 | 去向 |
| --- | --- |
| 读文字、画页图、看哪页有图片（`youzi/pdf.rs`，约 430 行） | **引擎已经有了**（引擎就是照它写的），Pomelo 删掉自己的，改调引擎 |
| 照片打包成 PDF（Pub2MD 用，`pdf::images_to_pdf`，约 50 行） | **进引擎**，照搬 |
| 文章导出拼 PDF：合并页、加链接、目录、标题（`print.rs` 的 `assemble`，约 80 行） | **进引擎**，照搬；前面「把文章排成 A4 页」（WebKit）留在 Pomelo |
| 把 PDF 画成图片（导出 Word 时公式变图，`print.rs` 的 `png_of_pdf`） | **引擎已经有了** |
| Pub2MD 的 Mathpix 上传、查进度、下载（`pub2md/mathpix.rs`） | **引擎已经有了**（分步、可续跑的接口就是照 Pub2MD 的需要做的） |
| Mathpix 把结果转成 Word / LaTeX（`/v3/converter`） | 可以顺手搬进引擎的 Mathpix 部分（约 60 行），也可以留着——计划里定 |
| Pub2MD 其余：拆块、模型整理、检查、提示词、搜索（约 5,000 行） | **留在 Pomelo**（这是 Pub2MD 的本事，不是 PDF 处理） |
| 知识库导入、Office 图片列表、导入助手、Seeker 读简历 PDF | 业务逻辑留，里面调 PDF 的地方换成引擎 |
| 知识库 PDF 和扫描件的页图（新） | 引擎负责画，Pomelo 负责什么时候画、给谁看（见下） |

要换的调用：`youzi/files.rs`、`office.rs`、`assistants/importer.rs`、`assistants/seeker/files.rs`、`assistants/pub2md/{job,source,mathpix}.rs`、`print.rs`，约 23 处。`sha256_hex` 不是 PDF 处理，留在 Pomelo。

## 已定的

- **知识库保留页图**（站主 2026-11-25 定）。可行，而且 Pomelo 已经有一半：知识库的 PDF 在原文件夹里读（不复制），柚子查知识库时能用 `view=look` 现场把某一页画出来给云端模型看（`knowledge.rs::look`）。推荐做法：
  - **用到时现画，不在建索引时存盘**：引擎画一页几十毫秒，原文件就在文件夹里。存盘的话最多 2,000 个文件、每页 0.3–0.7 MB，很占空间，原文件一改还得重画。
  - **照引擎「每次都给页图、模型自己决定」的原则**：检索命中 PDF（含扫描件）的段落时，把那一页的页图随段落一起给能看图的模型（一次最多 6 段，约 9 千 tokens）；`view=look` 照旧能看任意页。
  - 「发给云端」关掉的来源，不给云端模型发图；本地模型看不了图就只给文字；原文件找不到时只给文字。
- **速度不能变慢**：建索引只要文字，读取时把页图关掉；页图都是现画。

## 要注意

- **Pub2MD 续跑**：Pomelo 现在把 Mathpix 任务编号存在任务文件里，接引擎后存的是引擎的续跑记录（`mathpix::Submitted`，可序列化）。升级那一刻做到一半的旧任务要能接着跑，专门处理、专门测。
- **原页图范围**：引擎画的是 CropBox（阅读器显示的范围），Pomelo 原来画 MediaBox；知网这类文件的原页图边缘会少一截。
- **扫描件 OCR 的时间**：每页约 0.5 秒，系统第一次加载识别模型 16–33 秒。放后台做，不挡建索引的其他文件。Vision 中文会漏「的」等字（简体整页错字约 10%），要逐字准确的走 Pub2MD / Mathpix。
- **接口是同步的**：`Document` 不跨线程，放 `spawn_blocking` 里用；取消用引擎的 `Cancel`。
- **模拟模式**：Pomelo 的模拟 Mathpix 换成引擎的 `FakeTransport::echo()`（feature `fake`），不联网、不记费。
- **日志**：引擎在编译期关掉 `log` 的 TRACE（防止 HTTP 库把密钥写进日志）；Pomelo 没用 TRACE，没有影响。
- **依赖写法**：`engine-pdf = { git = "https://github.com/elenskye/engine-pdf", tag = "v0.x.y" }`；升级改 tag，回退改回上一个。
- 规矩：Pomelo 的改动守 Pomelo 的 `CLAUDE.md`（版本程度先问站主、数据结构和功能范围先问、Git、正式版）；引擎的改动（照片打包、拼 PDF、可能的 Mathpix 转换）在 engine-pdf 仓库做，守它的 `CLAUDE.md`（Codex 实施、Claude 审核、打 tag）。

## 计划要回答 / 要站主定的

1. 这次是 Pomelo 的哪种程度（现在 1.0.6）、分不分 Phase；和 engine-pdf `v0.6.0` 怎么对版本；要不要排到 Pith 之前。
2. 扫描件进知识库：默认开还是给开关；整本扫描书（几百页）怎么排队、怎么显示进度。
3. 页图给模型：检索命中就带图，还是只在模型要时（`view=look`）给；要不要给最近用过的页图做小缓存。
4. Mathpix 转 Word / LaTeX 搬不搬进引擎。
5. 引擎新增「照片打包」「拼 PDF（页、链接、目录、标题）」的接口长什么样（以后 Pith 的 PDF 编辑器也要用：整理页面、编辑目录）。
6. 每处替换怎么核对旧行为：文字 PDF 的知识库分段逐字一致；原页图比宽高和样子；导出的文章 PDF 链接、目录、标题都在；Pub2MD 用模拟服务跑完整任务、中途退出再续跑不重复上传。

## 验收场景

- 文字 PDF 进知识库：分段和以前逐字一致，搜索、引用、点开原文件照旧。
- 扫描 PDF 进知识库：能搜到、引用带页码；断网也能建。
- 柚子回答引用 PDF 的段落时，能看图的云端模型拿到那一页的页图；「发给云端」关掉的来源不发图。
- Pub2MD：照片、PDF、Word 三种都能跑完；原页图看起来和以前一样（知网文件边缘少一截除外）；中途退出再继续不重复上传、不重复收费；旧版本留下的半截任务能续跑。
- 见字如面导出 PDF：页、链接、目录、标题和以前一样，文字能选能搜。
- 坏文件、加密文件给出明确提示；建索引速度和以前一样。
